# Risk Register

| #   | Risk                                                                         | Likelihood | Impact           | Mitigation                                                                                                               | Owner         |
| --- | ---------------------------------------------------------------------------- | ---------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------- |
| R1  | Scope too large for 8 h/week                                                 | High       | High             | Thin vertical slices, milestone gates, public backlog                                                                    | Project owner |
| R2  | Beautiful UI hides incomplete backend                                        | High       | High             | Every milestone has a DB-backed integration test gate                                                                    | Engineering   |
| R3  | Cross-client data leak (BOLA/IDOR)                                           | Medium     | Critical         | Deny by default, per-record policy, negative API tests per role                                                          | Engineering   |
| R4  | Lost update / duplicate project or invoice                                   | Medium     | High             | `version` optimistic locking, idempotency keys, unique constraints                                                       | Engineering   |
| R5  | Unsafe file uploads                                                          | Medium     | High             | M7: allowlist, signature and active-content checks, attachments only, sandbox CSP, CLEAN-only publish (ADR-044); see R25 | Engineering   |
| R6  | Unsafe third-party AI handling                                               | Medium     | High             | Off by default; consent, scope, human review (M13+)                                                                      | Project owner |
| R7  | Mixed currencies corrupt KPIs                                                | Low (M3)   | High             | BigInt minor units, decimal strings, per-currency totals; no cross-currency sums without FX (ADR-023)                    | Engineering   |
| R8  | Overpromising legal e-signature / invoicing                                  | Medium     | High             | "Operational approval" labels; legal review before real use                                                              | Project owner |
| R9  | Excessive design iteration                                                   | Medium     | Medium           | Fixed tokens (spec §7.2), screen contract per milestone                                                                  | Engineering   |
| R10 | App does not run on owner's Windows machine                                  | Medium     | High             | Pinned versions, `docs/16_WINDOWS_SETUP.md`, CI fresh install                                                            | Engineering   |
| R11 | Docker Desktop not running / unavailable                                     | Medium     | High             | Documented start steps; DB tests marked NOT RUN if unavailable                                                           | Project owner |
| R12 | Prisma 7→8 / TypeScript 7 toolchain churn                                    | Medium     | Medium           | Pin stable versions, no RC; upgrade via ADR                                                                              | Engineering   |
| R13 | In-memory login rate limit bypassed with several instances                   | Low (now)  | High (at deploy) | Shared store before scaling out (ADR-007)                                                                                | Engineering   |
| R14 | Public repo leaks a secret or personal data                                  | Low        | High             | `.gitignore`, placeholder-only `.env.example`, secret scanning in CI (M11), noreply commit email                         | Engineering   |
| R15 | No production email provider: password reset cannot reach real users         | Medium     | Medium           | Dev sink + disabled transports (ADR-016); invitations work via the shown link; owner to choose a provider                | Project owner |
| R16 | Fixture-shaped gitleaks allowlist could hide a real secret of the same shape | Low        | Medium           | Allowlist exact fixtures + one narrow passphrase convention only, no paths (`.gitleaks.toml`)                            | Engineering   |
| R17 | Deals marked WON by override instead of a client-accepted proposal           | Low (M4)   | Medium           | `deals.override_won` for managers only, a reason is required and shown in history (ADR-024); M4 adds the proposal path   | Engineering   |
| R18 | Absolutely positioned content escapes scroll containers and breaks 360px     | Low        | Medium           | Scroll containers are `relative`; every E2E page asserts no horizontal overflow at 360px                                 | Engineering   |
| R19 | Clients read "accept" as a binding signature                                 | Medium     | High             | Operational-approval wording everywhere (ADR-029); legal review before binding use                                       | Project owner |
| R20 | A portal user sees another organization's data                               | Low        | Critical         | Portal API pinned to the user's organization; 404 for anything else; CLIENT in every matrix row                          | Engineering   |
| R21 | Proposal PDF cannot show Arabic text (built-in Latin fonts)                  | Medium     | Medium           | Print view shows it correctly; embed a Unicode font with RTL shaping (ADR-033)                                           | Engineering   |
| R22 | Production image ships the whole dependency tree (831 MB)                    | Medium     | Low              | Works and is non-root; prune to API runtime dependencies before production (M11)                                         | Engineering   |
| R23 | A test-only hook (fault injection) exists in production code                 | Low        | Low              | Only `AppDeps.hooks`; `server.ts` never sets it; documented in ADR-038                                                   | Engineering   |
| R24 | Projects from override-won deals have no agreed scope baseline               | Medium     | Medium           | Conversion refused; manual projects are visibly "without a deal"; change requests (M8) need a baseline                   | Project owner |
| R25 | Malware inside an allowed file type (no antivirus engine yet)                | Medium     | High             | Built-in checks only (ADR-044); files never render inline; add ClamAV or a provider scanner with hosting                 | Project owner |
| R26 | Losing FILE_ENCRYPTION_KEY makes every stored file unreadable                | Low        | High             | Key in the secret manager; back it up with the files; restore drill before launch (M11)                                  | Project owner |
| R27 | Local file storage is single-instance and needs its own backups              | Medium     | Medium           | Volume in the image; storage port ready for S3-compatible storage once hosting is chosen (ADR-043)                       | Project owner |
| R28 | Extra work billed without the client's agreement                             | Medium     | High             | Budget changes only on client acceptance; extra-work tasks need an accepted change or an audited exception (ADR-051/052) | Project owner |
| R29 | Comment threads carry information the client should not see                  | Medium     | Medium           | Threads are labelled as client-visible for staff; internal notes stay on tasks and time; in-app review of wording        | Engineering   |
