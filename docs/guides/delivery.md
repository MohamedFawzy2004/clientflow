# Guide: Delivery (project managers and team members)

PMs run projects; members work on the projects they belong to.

## Starting a project

- A won deal becomes a project with **Convert to project** (PM, Admin or Owner). Choose the manager,
  start and due dates. Converting twice is impossible: a retry returns the same project.
- Projects without a deal can be created directly by a PM, Admin or Owner.
- On the project page: add **members**, set **milestones**, and tick the handoff checklist.
- **Share** the project with the client's portal users when they should see it. Unsharing takes
  effect immediately.

## Tasks

- **Tasks** shows a board (To do, In progress, Blocked, In review, Done). Each card also has a status
  menu, so you never need to drag.
- A task has an assignee, milestone, due date, priority and estimate. Overdue tasks are marked.
- Work outside the accepted scope must point to a change request, or carry a one-line reason. This
  keeps unpaid extra work visible.
- Members log time on a task (**Log time**): the date, minutes, billable or not, and a note. **Time**
  shows the project's logged hours.

## Change requests

1. **New change:** describe what the client wants.
2. The PM adds the estimate: scope, work items, hours, price and any new due date (**Save estimate**).
3. Submit it. An Owner or Admin approves it for the client (**Approve for the client**) or returns it.
4. Send it to the client, who accepts or declines in the portal.
5. Accepting adds the work items as tasks and updates the project's scope history.

## Deliverables

1. Upload the file under **Files** (PDF, images, Office files and others; each file is checked and
   stored encrypted).
2. Create the deliverable, attach the file as a version and **Publish** it to the client.
3. The client approves it, asks for a revision, or rejects it, always with a reason when it is not
   an approval. Add a new version to answer a revision.
4. Comments on deliverables and changes are shared with the client. Edits keep their history.

## Your dashboard

PMs and members see their open tasks, overdue items, milestones due this week, and deliverables
waiting for the client.
